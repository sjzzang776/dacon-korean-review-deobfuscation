참고 저장소에서 가져온 것 ② · KoCharELECTRA

태거 몸통 대신 "후보 채점기"로 쓰다

참고 저장소는 KoCharELECTRA 상위 층을 태거에 얹었습니다. 여기서는 구조상 ③의 질문, 즉 "후보 중 어느 것이 자연스러운가"가 핵심이라, ELECTRA 의 원래 학습 과제인 바뀐 글자 찾기(discriminator)를 그대로 채점에 썼습니다. 가장 큰 단일 개선이었습니다(0.9871 → 0.9922).

계산 방법

1. 후보를 끼운 문장을 넣는다

discriminator 는 글자마다 "원래 글자가 아니라 바뀐 글자 같다"는 logit 을 냅니다. 클수록 어색한 글자입니다.

2. 후보 ± 3글자 구간을 채점한다

구간 안 글자들의 −logit 합이 그 후보의 문맥 점수입니다. 클수록 자연스럽습니다.

  • 틀린 후보를 넣으면 그 글자뿐 아니라 주변 글자까지 어색하다고 판단하는 경우가 많았습니다. 그래서 후보 글자만이 아니라 앞뒤 3글자를 함께 채점합니다.
  • logit 을 확률(sigmoid)로 바꾸면 대부분 0 근처로 몰려 차이가 사라져서, logit 을 ±10 으로 자른 값을 그대로 씁니다.
  • generator(빈칸 맞히기)도 시험했지만, discriminator 와 함께 쓰면 추가 이득이 없었습니다.
  • 이 채점기로 바로잡힌 예로는 받침이나 초성 하나 차이로 뜻이 달라지는 단어들이 있었습니다.

원본 정리 문서에는 실제 검증 문장으로 계산한 글자별 점수와 바로잡힌 문장이 있었지만, 대회 데이터라 이 공개본에서는 뺐습니다.

최종 결합 · 안 된 것 · 규칙

서로 다른 문장을 맞히는 두 방식을 합치다

LLM(Qwen) 문맥을 쓴 11b(0.9915)와 KoCharELECTRA 를 쓴 13b(0.9922)는 평균은 비슷했지만 서로 다른 문장을 맞혔습니다(13b 가 나은 문장 153개, 11b 가 나은 문장 136개). 그래서 문맥 점수를 모두 더했습니다.

최종 점수 = 난독화 유사도 + 1.0 × Qwen + 0.5 × 글자 언어모델 + 0.5 × 문자 5-gram + 1.0 × KoCharELECTRA  → 0.9937
  • 11b 와 13b 가 둘 다 틀린 문장 중 일부(사자성어, 외래어 음식 이름 등)를 결합이 맞혔습니다.

해 보니 안 됐던 것

  • 태거 점수를 노이즈 채널 빔 서치에 직접 더하기: 태거가 과신해서 하락
  • 가린 어절을 맞히는 빈칸 채우기 모델을 처음부터 학습: 학습 신호 부족으로 0.9583 → 다음 글자 예측 방식(글자 언어모델)으로 바꿔 해결
  • 어절 빈도 가점, "애매하면 기존 답 유지" 문턱: 효과 없음
  • KoCharELECTRA generator 미세조정: discriminator 와 함께 쓰면 이득 없음

규칙과 재현

  • 공개 가중치 모델만 사용: Qwen2.5-1.5B, KoCharELECTRA (둘 다 Apache-2.0). 3B·72B Qwen 은 라이선스 제약으로 제외
  • 외부 데이터 없음. 생성 문장은 train 으로 미세조정한 모델이 만든 것
  • 모든 가중치(문맥 점수 비율 등)는 검증 분할에서만 정하고, test 는 train 전체로 다시 학습한 모델로 예측
